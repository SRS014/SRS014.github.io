# Sohan — personal portfolio

Static portfolio for **Sohanur Rahman Sohan**, Power Platform Developer & Solution Builder.
Built with [Astro](https://astro.build) (MIT), styled with the Fusion Sky brand tokens, hosted free on
GitHub Pages. No server, no tracking, no cookies.

## Run it locally

Needs Node.js 20 or later (tested with 24).

```
npm install          # once
npm run dev          # live preview at http://localhost:4321
npm run build        # build the static site into dist/
npm run preview      # serve dist/ at http://localhost:4321
npm run check:links  # after a build: fails if any internal link or image is broken
```

## Edit the content

Almost everything lives in **`src/data/profile.ts`**:

| What | Where in `profile.ts` |
|---|---|
| Name, designation, tagline, positioning, email, links | `site` |
| About text, "What I build" cards, skills | `about` |
| Jobs and bullet points | `experience` |
| Education, honours | `education`, `honors` |
| Certifications (active / previously held / Applied Skills / training) | `certifications` |
| Projects (currently **placeholders**) | `projects` |
| Blog posts on the Writing page | `writing` (add new posts at the top) |
| Printable resume summary | `resumeSummary` |

Rules that keep the site trustworthy:
- Never add a phone number or home address.
- Keep expired certifications in `certifications.previous`, never in `active`.
- The headline designation is "Power Platform Developer & Solution Builder".
- Replace a placeholder project only with a real one: problem, what you built, tools, outcome, and a client
  name only if you may share it. Set `placeholder: false` and fill the fields.

Pages are in `src/pages/` (one file per page). The layout, header and footer are in `src/layouts/Base.astro`,
and the styles are in `src/styles/global.css`. Colours come only from `src/styles/tokens.css`, which is a copy of
`NewBrandAssets/tokens/tokens.css`. Copy it again if the brand tokens change.

- Photo: `public/images/sohan-320/640.webp|jpg` (from the 1000 px square photo).

- `public/og-image.png` (1200 x 630 social preview) and `public/resume.pdf` (printed from the `/resume/` page,

```
npm run build
<python with Playwright>  scripts/make_assets.py     # e.g. the Fusion Content Studio venv

```

## Quality checks

`scripts/qa_pages.py` (Python + Playwright, Edge channel) screenshots every page at 360, 768 and 1280 px into
`screenshots/`, checks for horizontal scrolling, and runs axe-core (WCAG 2.2 AA) on each page. It writes
`screenshots/qa-report.md`.

## Deploy (GitHub Pages)

The workflow in `.github/workflows/deploy.yml` builds and publishes the site on every push to `main`.

1. Create the repository **`SRS014.github.io`** on GitHub. That gives the address https://srs014.github.io.
   With any other repository name, set `base: "/<repo-name>"` in `astro.config.mjs`.
2. Pushing a workflow file needs the `workflow` scope: `gh auth refresh -h github.com -s workflow`.
3. `git remote add origin https://github.com/SRS014/SRS014.github.io.git` and `git push -u origin main`.
4. In the repository: **Settings → Pages → Source: GitHub Actions**. The site is live after the first run.

To update the site later: edit `src/data/profile.ts`, run `npm run build` and `npm run check:links`, commit, and
push. GitHub Pages redeploys automatically.
